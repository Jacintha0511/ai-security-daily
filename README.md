# AI 安全研究观察站

公开的 AI／Agent 安全动态日报，重点关注记忆投毒、来源追踪、行动权限与提示注入。

网站地址（启用 Pages 后）：https://jacintha0511.github.io/ai-security-daily/

## 做什么

- 每日从 arXiv、GitHub 和已配置的 RSS 收集公开动态，规则预筛最多 3 篇论文、5 个项目、3 篇报道。
- 页面提供当天产出状态、来源覆盖、历史日报、公开周报、类别与关键词筛选。
- 星数保留 45 天快照，比较真实时间窗口的净变化；首日不推算历史。
- 规则采集不调用模型 API；论文、Top 1 项目及前两篇报道的解析由本机 Codex 账号定时生成并缓存，不生成或发布私人科研 idea，不读取研究 API 密钥。

规则预筛不等于学术质量判断，摘要不等于全文核验，预印本不等于正式发表。没有可用 RSS 的公众号明确显示“待接入”。

## 自动运行

GitHub Actions 使用标准 Ubuntu runner：北京时间每天 01:15 生成日报、01:45/08:15/10:15 检查补跑；周日 09:15 生成周报。调度可能排队或延迟，不保证分钟级准时。公开仓库长期无活动可能被 GitHub 停用定时工作流，请关注实际运行记录。

工作流在同一并发组串行执行，将公开状态和快照提交到 `data/`，再部署静态站点。历史不依赖 Actions 缓存。全部来源失败时保留之前有效报告并更新失败状态；后续健康检查使该次 Actions 显示失败。

首页按北京时间判断“今天是否产出”。如果工作流在安装依赖等早期阶段失败、无法发布状态，旧站点也会显示报告日期已过期并提供 Actions 入口。

## 本地使用

Python 3.12+：

```bash
python -m pip install -r requirements.txt
python -m unittest -v
python daily.py daily
python daily.py weekly
python daily.py build
python -m http.server 8787 --directory dist
```

`daily --force` 显式重新采集；否则同日已有可用结果且只有待接入订阅时不会重复请求。GitHub Actions 自动提供当前仓库的短期 `GITHUB_TOKEN`；本地可选配置只读 GitHub token 来提高限流额度，不要提交 token。

## Pages 首次启用

仓库 Settings → Pages → Source 选择 **GitHub Actions**。在 Actions 中手动运行 **Public daily and Pages**，选择 `all` 和 `force=true`。部署成功后访问网站，检查报告实际日期和运行链接。手动运行成功不代表已经验证下一次定时触发。

## 发布边界

`data/state.json` 只含公开字段，用于持久化条目、star 快照和采集状态；不部署到 Pages。部署产物由明确的资产与报告列表构建，不复制整个工作区。网页通过 `textContent` 渲染外部文本，只允许 http/https 来源链接。

配置和历史文件也在公开仓库中，不应填入私人 RSS 地址、访问凭据、未发表 idea 或私人研究材料。不要把本地研究工程的 `.research` 或 `.env` 同步到此仓库。


## 全文解析与公众号

本机 Codex 任务每天北京时间 02:00 启动，03:45 仅补跑未完成项。电脑须开机、联网并保持应用运行；不使用研究模型 API，但会占用 Codex 账号额度。详见 LOCAL_AUTOMATION.md。

论文版本、项目 commit 和材料指纹用于复用解析；缺失原图、发表证明或独立复现时明确显示部分解析。解析按钮跳转静态详情页，点击本身不调用模型。

公众号通过本机 WeRSS 订阅读取，扫码由用户完成；会话、原文和数据库都放在 git 忽略的本机目录。公开数据只含最近 24 小时文章的元数据、简短介绍与点评。未授权或过期不会被报告为无更新。

Publish reading analyses 工作流只合并本地公开报道和部署，不重新筛选论文。基础日报与解析分开更新，保持原推荐入口稳定。


## 推荐与历史浏览

历史日报通过 `?view=archive&date=YYYY-MM-DD` 定位；日期高亮、当期来源和正文同步切换，切日期会清空搜索与类别筛选。日报保存原推荐，早期日期可能包含旧规则选出的低 star 项目。

普通项目默认至少 100 star 且 180 天内有提交；登记研究基准可例外。通过粗筛后，优先主线相关、近 30 天提交或有可验证净增长的候选，再比较有效增长、登记基准和 star。低 star 项目保留在观察池，不凑推荐数量。此规则只筛元数据，不能证明代码质量，Top1 解读须另外核查代码与实验。阈值在 `config.json` 的 `repo_policy` 修改。

`node --test test_site.cjs` 验证历史深链接、日期切换、过滤重置、异步响应乱序、读取失败和返回导航；Python 测试覆盖项目门槛及基准例外。论文讲解写法见 `LOCAL_AUTOMATION.md` 的新要求。


## 阅读体验 v2

首页最多一篇重点、两篇备选和一个项目。`python reading.py sync` 从白名单公开字段生成 `data/library.json`，保存按材料版本绑定的精选记录；重复运行和重启不会把同一版本重新当作新精选。新版本需有明确实质变化才能再次精选，没有新内容则保留最近一期的真实日期。首次整理的旧导读有单独说明。

资料库搜索覆盖历史公开推荐；更多方向还包含未全文评读的公开候选。收藏、已读和不感兴趣只保存在当前浏览器，不回传服务器。跨版本分别记录，原始日报保持原样。论文官方代码的低-star 例外需要在 `verified_paper_repos` 中登记仓库与经核实的公开论文链接，不能据 README 自称官方就自动放行。

导读按三分钟概览与可展开详解分层，保留版本、原文证据、核查限制和返回位置。发布前运行 Python 测试、Node 测试、公开字段校验和静态构建。所有维护可在后台完成，无需桌面控制。
